三种拿直链的办法

  • 方案一 · 仓库直链（推荐）：把 cover.png 推到仓库，用 raw.githubusercontent.com 地址。永久有效，改图重新推即可。
  • 方案二 · 图床：传 sm.ms / imgur，拿到 https://i.xxx/xxx.png。最快，几十秒搞定。
  • 方案三 · 走隧道：如果你不想动仓库，把图放进 frontend/assets/，用 https://你的隧道域名/assets/cover.png。缺点是隧道一断链接就废。
坑：GitHub 的 github.com/.../blob/... 是网页地址，填进去预览会是白板。必须是 raw.githubusercontent.com。
06详细说明 必填技术栈 / 功能亮点 / 运行方式
表单提示词已经点明了三块：技术栈、功能亮点、运行方式。下面这版按这三块排好了，直接整段粘。
【一句话定位】 粘贴一条网传消息，自动完成关键词提取 → 全网检索 → 证据双栏核对 → 三级可信度分级 → 查证卡生成，输出每一条依据都可点击跳转的结论。核心主张：结论有依据，来源可追溯。 【技术栈】 · 后端：Python 3.10+ / FastAPI / Uvicorn，监听 0.0.0.0:8000 · 前端：原生 HTML + CSS + JavaScript，零框架零构建，单文件渲染 · 流水线：六模块解耦 —— 输入 → 关键词 → 检索 → 核对 → 分级 → 卡片 → 输出，每模块可独立替换 · 三引擎：本地规则引擎（知识库命中）/ 在线融合引擎（本地与在线并行 + 可解释仲裁）/ 大模型引擎（三段式提示词），输出同一份数据结构，前端无感切换 · 知识层：通识共识库 121 条（覆盖人、动物、人与动物、人与生活、人与自然、人与社会、社会与国家、人与教育 8 大领域）+ 全国高校库 322 所 + 已核实事实库 13 组 · 输入层：Windows 系统 OCR 识别截图与图片；TXT / MD / CSV / PDF / DOCX / XLSX 六种文件本地解析 · 依赖仅 8 项：fastapi、uvicorn、pydantic、openai、python-multipart、pillow、python-docx、pypdf、openpyxl、winsdk · 规模：后端 Python 约 5300 行 / 20 个模块，前端约 2300 行 【功能亮点】 1. 证据强制绑定来源 —— 每条依据必须挂 source_url，系统层面禁止"只给结论不给证据"，这是与普通 AI 问答最本质的区别。 2. 双栏证据对照 —— 左侧"支持原文的依据"、右侧"与原文矛盾的证据"并排呈现，不做隐藏式取舍，读者自己看得见分歧。 3. 三级可信度分级 —— 属实 / 不实 / 存疑，配合 0-100 置信度与环形进度，边界案例不强行给结论（证据不足时输出"存疑"而非硬判）。 4. 来源可信度打分 —— 按域名分级（政府 .gov.cn、学术、主流媒体、一般站点），并给出 A/B/C/D 可信度标签与分数，来源不是平等罗列。 5. 在线融合仲裁 —— 本地权威层命中且在线一致则上调置信度；两侧结论差 1 档取更保守一侧；差 2 档以上按进入证据的来源可信度定性。规则全程可解释，不做黑箱覆盖。 6. 七个独立结果模块 —— 结论 / 依据 / 来源清单 / 分歧说明 / 风险与局限 / 核查元信息，分模块呈现不堆砌；仅当来源冲突时才出现"分歧说明"，不强行二选一。 7. 多种输入方式 —— 截图识别、导入图片、导入文件（PDF / Word / Excel / TXT / MD / CSV）、长段逐句核查，覆盖真实使用场景。 8. 查证卡导出 —— Canvas 生成 PNG，可直接分享；支持批量查证（单次 ≤10 条）。 【运行方式】 环境要求：Python 3.10 及以上 1) 安装依赖 cd backend pip install -r requirements.txt 2) 启动服务 python run_server.py 服务监听 0.0.0.0:8000 3) 浏览器打开 本机：http://127.0.0.1:8000 局域网：http://<本机IP>:8000（需防火墙放行同网段 8000 端口） 公网：见上方演示地址，口令 VERITAS-2026 4) 调用示例 curl -X POST http://127.0.0.1:8000/api/verify \ -H "Content-Type: application/json" \ -d "{\"text\":\"手机整夜充电会严重损坏电池\",\"engine\":\"auto\"}" 主要接口：/api/verify（主查证）、/api/verify/segment（长段逐句）、/api/verify/batch（批量）、/api/input/extract（文件提取）、/api/input/ocr（图片识别）、/api/card/{id}/html（卡片快照）、/api/health（健康检查） 【自测情况】 7 例语义用例全部通过（含 2 例真实陈述、3 例典型谣言、2 例证据不足边界），12 项接口测试全部通过。实测"手机整夜充电会严重损坏电池"：判定不实，置信度 90，本地知识库与在线检索结论一致，检索到 10 条来源，其中支持 3 条、矛盾 3 条，仲裁动作 confirm。
