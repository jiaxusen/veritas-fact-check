> 依据《查证工具产品实现手册》开发 · WaytoAGI AI切磋大会 · 1024超能Coding周末 · 郑州站 · 查证（AI侦探社）赛道
**核心主张：结论有依据，来源可追溯。**

## 二、产品能力
输入一段网传消息，系统自动完成 **关键词提取 → 全网检索 → 信息核对 → 可信度分级 → 查证卡生成 → 页面展示** 全链路，输出带来源的结构化查证卡。

## 三、查证内容分模块作答
结果区严格分为 **7 个独立模块**，互不混杂：
| 模块 | 内容 |
|---|---|
| **02 查证结论** | 大字结论徽章 + 置信度环形进度 + 结论说明 |
| **03 核对依据** | 左「支持原文的依据」/ 右「与原文矛盾的证据」双栏对照，每条带来源链接与证据强度条 |
| **04 来源清单** | 来源卡片，含标题、域名、发布时间、可信度标签与分数、摘要，可点击跳转 |
| **05 分歧说明** | 仅当来源冲突时出现，并列说明分歧点，不强行二选一 |
| **06 风险与局限** | 核查局限、使用建议、免责说明 |
| **07 核查元信息** | 卡片编号、核查时间、引擎、耗时、原文长度、判定依据、关键词标签 |

### 三引擎设计
| 引擎 | 触发条件 | 说明 |
|---|---|---|
| **本地查证引擎** | `engine=local` | 规则化关键词提取 + 通识/领域/高校/已核实事实库 + 联网检索 |
| **在线融合引擎**（默认 `engine=auto`） | 在线查证台可用时自动启用 | 本地流水线 + 在线查证台**并行**，证据与结论融合后裁决 |
| **大模型引擎** | 配置 `{PROVIDER}_API_KEY` + `{PROVIDER}_BASE_URL` | 真实检索 + LLM 三段式提示词核对 |
三引擎输出**同一份查证卡数据结构**，前端无感知切换；在线不可用时 `auto` 自动降级为本地引擎。

### 在线融合引擎（本地 + 在线查证台）
在线侧补齐了本地匮乏的三项能力：**多事实点逐条判定**、**证据打分与原文定位**（`score / exact / rank / locator`）、**官方与辟谣类来源高命中检索**。

配置 `backend/data/remote.json`（支持环境变量覆盖）：
```json
{
  "enabled": true,
  "base_url": "https://chazheng-ai.app.workbuddy.host",
  "sharecode": "YEQ2COGZKU",
  "pass": "VERITAS-2026",
  "timeout": 45, "retries": 2, "cache_ttl": 900
}
```
环境变量：`CHAZHENG_BASE_URL` / `CHAZHENG_SHARECODE` / `CHAZHENG_PASS`；`VERITAS_REMOTE_OFF=1` 可一键关闭在线侧。

融合裁决规则（始终可解释，不做黑箱覆盖）：
| 场景 | 处理 |
|---|---|
| 本地命中通识共识 / 已核实事实库 | 本地优先，在线一致则上调置信度，不一致则保留本地并下调置信度 |
| 本地判为存疑 | 在线有明确结论时采纳在线结论，并保留其局限说明 |
| 两侧相差 1 档且方向一致 | 取更保守的一侧（如本地「基本属实」+ 在线「部分属实」→ 部分属实） |
| 两侧相差 ≥2 档 | 按真正进入证据的来源可信度较高者定性，并下调置信度 |

## 六、可信度分级规则
| 结论 | 判定条件 | 置信度 |
|---|---|---|
| **属实** | 多个可信来源一致支持，未发现矛盾证据 | 75-98 |
| **不实** | 多个可信来源一致否定，矛盾证据充分 | 75-98 |
| **存疑** | 证据不足、来源过少、或支持与矛盾并存 | 20-60 |
**硬约束**：每条依据必须对应来源链接，禁止「仅给结论不给证据」。
## 七、本地部署
### 环境要求
- Python 3.10+
### 启动步骤
```bash
cd backend
pip install -r requirements.txt
python run_server.py
```
浏览器打开 `http://127.0.0.1:8000`
### 三种访问方式
| 场景 | 地址 | 是否需要口令 |
|---|---|---|
| 本机 | `http://127.0.0.1:8000` | 免密 |
| 局域网（同一 WiFi） | `http://<本机局域网IP>:8000`（当前 `192.168.1.199`） | 免密 |
| 公网（Cloudflare 隧道） | `https://combat-bloggers-districts-nails.trycloudflare.com` | **需要口令** |

服务默认监听 `0.0.0.0:8000`。局域网访问需要一条防火墙入站放行规则（仅放行同网段）：
```powershell
netsh advfirewall firewall add rule name="verify-lab-8000" dir=in action=allow protocol=TCP localport=8000 remoteip=localsubnet
```
**注意**：Cloudflare 快捷隧道的域名是随机生成的，隧道重启后会变更。

### 公网访问口令
配置文件 `backend/data/auth.json`：
```json
{ "enabled": true, "key": "VERITAS-2026", "public_only": true }
```
- `public_only: true` → 仅公网来源要求口令，本机与局域网免密直通（按 Host 判定，`localhost` / `127.*` / `192.168.*` / `10.*` / `172.16-31.*` 均视为内网）
- 校验通过后写入 `vlab_key` Cookie，有效期 30 天
- 也可用环境变量 `VERITAS_ACCESS_KEY` 覆盖，无需重启即可生效
- 口令仅用于防止链接被随手转发（在线检索有额度），不是强鉴权
### 启用大模型引擎（可选）
```bash
set MODEL_PROVIDER=openai
set OPENAI_API_KEY=你的密钥
set OPENAI_BASE_URL=https://api.openai.com/v1
set OPENAI_MODEL=gpt-4o-mini
```
重启服务后 `/api/health` 返回 `"engine": "llm"`。

## 九、避错清单落实
| 手册问题 | 本产品对策 |
|---|---|
| 主流程跑不通 | 先做 MVP 闭环，加分项在闭环后叠加 |
| 检索结果杂乱 | 实体优先提取关键词，限制 3 条 |
| 结论无依据 | 每条依据强制绑定 `source_url`，自测有断言校验 |
| 来源冲突无法处理 | 并列呈现分歧 + 输出存疑 + 分歧说明模块 |
| 演示报错 | 三轮自测 + 接口测试 + 前端资源验证全通过 |
